# Goal Prompt

Create a new Rust CLI crate that scrapes unit data (including base stats, weapons, and upgrades) from all Grimdark Future armies on Army Forge, caching raw pages locally, and outputs them as versioned YAML files.

**Success criteria:**
- New crate `crates/data-collector` exists and compiles with zero clippy warnings under workspace lints
- CLI has a two-phase architecture: fetch (network) and parse (local cache)
- Fetch phase downloads all ~28 army pages with generous rate limiting (2-3s delay between requests) and saves raw HTML to a local cache directory
- Parse phase reads exclusively from local cache — zero network requests during parsing
- Subsequent runs use cached data by default; a `--force-refresh` flag re-fetches stale data
- Handles the dropdown navigation for Battle Brothers, Prime Brothers, and Havoc Brothers subfactions
- Extracts unit stats: name, size, cost, quality, defense, tough, special rules, weapons (with range, attacks, AP, special)
- Extracts upgrade options grouped by category with name, rules/description, and cost modifiers
- Outputs one YAML file per army in kebab-case (e.g., `alien-hives.yaml`)
- YAML files are versioned with the army's version number as the top-level key

**Boundaries:**
- In scope: Grimdark Future armies only, Army Forge website, PDF preview pages, CLI interface, upgrade parsing, local HTML caching
- Out of scope: Other OPR games, automated scheduling, GUI, API integration, real-time updates, PDF file downloads, cache invalidation strategies beyond `--force-refresh`

**Constraints:**
- Must pass all workspace clippy lints (pedantic, nursery, no unwrap, no panic, no indexing, etc.)
- Must use workspace dependencies where available (serde, tokio, etc.)
- Rate limiting: minimum 2-3 second delay between HTTP requests during fetch phase
- Cache-first: parsing never makes network requests; all data comes from local cache
- Fetch phase downloads once and caches; re-runs skip fetching if cache exists (unless `--force-refresh`)
- Must handle network errors gracefully without panicking
- YAML output must be human-readable and well-formatted
- Edition 2024 Rust

**Verification contract:**
1. Run `cargo clippy --all-targets --all-features -p data-collector` with zero warnings
2. Run the fetch phase and confirm all raw HTML pages are cached locally with timestamps
3. Run the parse phase from cache and verify it creates YAML files for all armies without any network requests
4. Run a second time without `--force-refresh` and confirm no HTTP requests are made (all served from cache)
5. Inspect at least 3 generated YAML files (including one with subfactions like Battle Brothers) to confirm version keys, complete unit stats, properly grouped upgrades, and valid YAML
6. Verify upgrade parsing accuracy by comparing a complex unit (like Hive Lord) against the web page
